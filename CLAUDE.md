# CLAUDE.md — hack-22572782-neuroforge

## Проект
Хакатон-кейс "Креативные индустрии": сервис умного подбора event-подрядчиков в Казахстане.
Полное ТЗ и разбор — см. `docs/architecture.md` (архитектура) и обсуждение в истории репозитория.
Датасет: `hackathon-dataset-anonymized` (66 профилей, .jsonl/.csv/.html preview) — лежит вне репо в `~/Downloads`, копируется в `data/raw/` при необходимости.

## Ключевое требование ТЗ (не нарушать)
- **Детерминизм**: один и тот же запрос → тот же порядок карточек. Ранжирование — чистый детерминированный код, без рандома и без зависимости от LLM temperature.
- **LLM только для текста объяснений**, не для фильтрации/ранжирования. temperature=0, промпт строго на заранее вычисленных фактах (без права придумывать).
- **Никакого файнтюнинга** на 66 записях — только готовые эмбеддинги + LLM через API.
- Жёсткий фильтр по `busy_dates` — подрядчик, занятый на дату заказа, не попадает в выдачу.
- Три явно различимых исхода: подобрали / категории нет в городе / кандидаты есть, но никто не проходит фильтры (с честным объяснением почему).
- Ответ до ~10 секунд, с fallback на шаблонное объяснение, если LLM API недоступен/таймаут — демо не должно падать вживую.
- Приоритет качества: объяснения > честная обработка редких/занятых/пустых случаев > скорость > UI.

## Правило: ничего не хардкодить
Это главная ранее словленная ошибка — architecture draft содержал скрытые хардкоды. Исправлять на корню:
- **Никаких enum-списков** городов/категорий/форматов/языков в коде. Все допустимые значения вычисляются динамически из датасета при старте (`set(p.city for p in profiles)` и т.п.). Новая категория/город/синтетический профиль в JSONL не должны требовать правки кода.
- **Веса скоринга** — только в `config.py` / `.env`, никаких магических чисел в `scoring.py`.
- **Набор soft-фич скоринга** — список функций-плагинов, не одна захардкоженная формула. Добавление новой фичи не должно трогать ядро.
- **Промпт для LLM** — отдельный шаблон-файл/константа в конфиге, не строка внутри кода логики.
- Единственное, что можно жёстко задавать, — **схема** данных (имена полей датасета), не их содержимое.

## Договорённости по стеку
- Backend: Python 3.11+, FastAPI + Pydantic.
- Эмбеддинги: считаются **локально** (`sentence-transformers`, мультиязычная модель) — не по API, чтобы убрать сетевую зависимость и рандомность с критичного (ранжирующего) пути.
- LLM для объяснений: Claude API, temperature=0, с кэшем объяснений по ключу `(candidate_id, normalized_query)` и шаблонным fallback.
- Датасет — в памяти при старте (66–100 записей, БД не нужна).
- UI — минимальный (форма), не приоритет по ТЗ.

## Git / рабочий процесс
- **По правилам хакатона push в GitHub должен делать Codex, не Claude Code.** Я пишу код, коммичу локально после каждого законченного куска работы (скелет, модуль, тесты и т.п.) — но **`git push` больше не выполняю**. После коммита сообщаю пользователю, что изменения готовы к пушу, и оставляю сам push на Codex/пользователя.
- Коммит `ea26853` (скелет проекта) был запушен Claude Code до введения этого правила — оставлен как есть, задним числом не переделывается.
- Merge в чужие/защищённые ветки и force-push — как и раньше, только с явным подтверждением (и в любом случае не мной, раз push теперь не моя зона).
- Не использовать `git add -A`/`git add .` вслепую — добавлять файлы по имени, проверять `git status` перед коммитом.
- Атрибуция коммитов и PR — по актуальному system-reminder на момент коммита (модель, под которой сделан коммит, может меняться в течение сессии).
