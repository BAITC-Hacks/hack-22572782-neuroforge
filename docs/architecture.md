# Архитектура NeuroForge

## Поток запроса

```text
Браузер → POST /recommend → проверка схемы и окна календаря
  → нормализация по справочникам каталога
  → город + категория
  → дата → бюджет → формат → длительность → язык
  → классификация FOUND / NO_CATEGORY / NO_MATCH
  → локальные эмбеддинги + детерминированный рейтинг → top-3
  → цитаты + проверенные факты → опциональный выбор акцентов LLM
  → карточки + причины отсева + трассировка
```

Один процесс FastAPI хранит каталог и индекс в памяти. Модель прогревается в
lifespan до готовности приложения. Это достаточно для 66 профилей; отдельная
БД для каталога и распределённый оркестратор здесь не нужны. SQLite используется
только как необязательный кэш выбора акцентов.

## Данные и валидация

Pydantic проверяет типы, непустые строки, неотрицательный бюджет и положительную
длительность. Пустые опциональные строки становятся null. Регистр и пробелы в
справочных значениях нормализуются относительно данных; списки городов,
категорий, форматов и языков вычисляются из каталога.

Окно календаря задано метаданными поставки в конфигурации: 23.09–31.12.2026.
Оно не выводится из минимума и максимума занятых дат. За его пределами возвращается
422: отсутствие записи не доказывает доступность.
Неизвестная категория или город дают NO_CATEGORY; неподдерживаемый формат или
язык внутри существующего каталога — NO_MATCH.

Основной JSONL обязателен; синтетическое дополнение опционально. Все ID уникальны.
Профили из дополнения обязаны содержать synthetic=true. Флаги synthetic,
price_imputed и city_imputed передаются в карточки и показываются пользователю.

## Фильтры и три исхода

Город и категория определяют исходный пул. Если он пуст — NO_CATEGORY.
Далее фильтры применяются в фиксированном порядке:

| Причина | Условие прохождения |
|---|---|
| busy_date | Даты запроса нет в busy_dates |
| budget | price_from_kzt ≤ budget_kzt |
| format | event_type входит в event_formats |
| duration | Часы не заданы, max_hours=null или max_hours ≥ duration_h |
| language | Язык не задан или входит в languages |

Площадки и люди используют тот же календарный фильтр.
Каждого исключённого кандидата считают один раз, по первой сработавшей причине.
Поэтому сумма rejection_breakdown равна pool_size − eligible_count.
found_count — число показанных карточек, максимум 3; оно может быть меньше eligible_count.
Если выживших нет, NO_MATCH включает текстовые причины.
Если их меньше трёх, FOUND объясняет неполную выдачу.
Занятость выводится общим сообщением, чтобы смена даты была понятна.

## Детерминированный рейтинг

Список фич задаётся реестром функций в scoring.py. Веса настраиваются через
NEUROFORGE_SCORING__<ИМЯ_ПОЛЯ>.

| Фича | Вес по умолчанию | Когда активна |
|---|---:|---|
| Семантическая близость описания к брифу | 0.55 | Есть непустой brief |
| Запас относительно начальной цены | 0.10 | Бюджет больше нуля |
| Запас допустимой длительности | 0.20 | Задана длительность |
| Число поддерживаемых языков относительно каталога | 0.15 | Задан язык |

Неприменимые фичи исключаются. Итог — сумма произведений, делённая на сумму
активных весов. Без брифа, языка и длительности цена остаётся единственным
активным признаком: меньшая начальная цена поднимет профиль выше.
Балл не оценивает качество подрядчика и не является вероятностью.

Сортировка: убывание балла, округлённого до шести знаков, затем ID по возрастанию.
LLM никогда не меняет кандидатов, доступность и порядок.
Модель эмбеддингов — paraphrase-multilingual-mpnet-base-v2, локально.
Кэш векторов подписан идентификатором модели, ID и описаниями.
Протокол EmbeddingProvider позволяет подменять модель в тестах; тестовые
хэш-векторы не используются в пользовательском сервисе.

## Объяснения с проверяемыми источниками

Для каждого из трёх кандидатов описание разбивается на предложения.
Предпочтение получают предложения, которых нет у соседних кандидатов,
и короткие цитаты. При наличии брифа выбирается ближайшее по эмбеддингам;
без брифа — первое подходящее предложение. Это характеристика профиля,
а не обещание точного соответствия всем свободным пожеланиям.

Цитата и начальная цена входят в карточку обязательно, если описание присутствует.
Дополнительные факты — язык, длительность и формат — вычисляются кодом.
LLM получает бриф, формат, дату, бюджет, цитату и словарь разрешённых фактов.
Её задача ограничена выбором одного или двух идентификаторов:

```json
{"fact_ids": ["language", "duration"]}
```

Проверяется точная структура, число элементов, отсутствие повторов и принадлежность
каждого ID разрешённому меню. Произвольный текст, неизвестные факты и лишние поля
не принимаются. Фразы строит renderer, поэтому модель не может подменить цену,
дописать рейтинг или обещать бронирование. Это ограниченный LLM-шаг внутри
детерминированного workflow, а не автономный агент с правом внешних действий.

Если данных для различения профилей нет и объяснения совпадают, ответ прямо
сообщает об этом. Описания остаются заявлениями поставщика данных: истинность
описанного опыта отдельно не проверяется.

## Отказоустойчивость и время

OpenAI и NVIDIA используют один клиент с настраиваемой цепочкой провайдеров.
Берутся только провайдеры с ключами. По умолчанию один вызов ограничен 4 секундами,
общая попытка — 5 секундами, повторные запросы SDK отключены.

Для карточек используется ограниченный пул из трёх потоков. Пайплайн ждёт
не дольше общего бюджета и подставляет факты при таймауте. Уже начатый сетевой
вызов нельзя принудительно остановить Python-потоком: он завершается по своему
сетевому таймауту. Новые фоновые потоки сверх лимита не создаются.

Кэш хранит только прошедший проверку JSON. Ключ включает полный промпт
(кандидат, ISO-дата с годом, запрос, цитата и факты), системную инструкцию и
конфигурацию провайдеров. Ошибки чтения/записи SQLite не ломают рекомендации.
Температура 0 и кэш не являются математической гарантией детерминизма LLM;
порядок карточек детерминирован независимо от неё.

Трассировка `explanation_sources` различает валидный ответ LLM, кэш,
шаблон без LLM, таймаут, недоступность и невалидный ответ. Поэтому успешная
рекомендация с fallback не выдаётся за успешную интеграцию с провайдером.

Без ключей, при ошибке API, невалидном ответе или превышении времени рендерер
использует штатный порядок проверенных фактов. Первый запуск требует загрузки
модели; офлайн-режим доступен после предварительной загрузки весов.

## Проверка

tests/ покрывают загрузку, фильтры, исходы, скоринг, кэш, HTTP API,
границы календаря, одинаковые цены без брифа, отказ LLM, недостоверный ответ,
недоступность SQLite и зависший провайдер.
scripts/run_demo_queries.py прогоняет пять сценариев на настоящей модели,
проверяет повторяемость порядка и изменение выдачи на другую дату.

Тесты с подменой модели проверяют логику, а не качество семантики.
Живой LLM-провайдер проверяется отдельно явным флагом --llm.
При изменении каталога нужно пересмотреть ожидаемые демо-исходы и его календарное
покрытие. Города и категории в код добавлять не требуется.
